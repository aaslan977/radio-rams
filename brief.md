# Бриф: Радиоприёмник (учебный проект / портфолио-кейс)

> **Изменение концепции (зафиксировано):** проект меняется с «аудио-плеера
> локальных файлов» на **интернет-радиоприёмник** в эстетике Braun/TP-7.
> Загрузка собственного файла и AUX-вход убраны полностью — устройство
> проигрывает только реальные живые интернет-радиостанции. Все открытые
> вопросы (раздел 7) закрыты — бриф готов к реализации.

## 1. Контекст продукта

Учебный проект в рамках курса по вайб-кодингу. Задача — сделать веб-радиоприёмник,
который одновременно решает две цели: (1) рабочий MVP, которым реально можно
пользоваться самому и показать другим людям по ссылке, (2) визуально сильный
кейс для портфолио.

Формат — **PWA (Progressive Web App)** без бэкенда: полностью клиентское
приложение (SPA), которое можно установить на телефон или десктоп как обычное
приложение. Источник звука — реальные живые аудиопотоки (интернет-радио),
подключаемые напрямую из браузера по их публичным stream-URL. Файлов
пользователя в системе больше нет — ни встроенных демо-треков, ни загрузки
своих (см. изменение концепции выше).

## 2. Целевые пользователи

| Роль | Сценарий | Частота |
|---|---|---|
| Автор (сам пользователь) | Использует как повседневный веб-радиоприёмник | Регулярно |
| Демо-аудитория (однокурсники, проверяющие курс, рекрутеры при просмотре портфолио) | Открывают публичную ссылку, пробуют переключение станций | Разово |
| Случайный посетитель по ссылке | Открывает URL, слушает одну из станций | Нерегулярно |

## 3. Ключевые сценарии

1. Открыть приёмник по ссылке (десктоп или мобильный браузер) — сразу доступна станция по умолчанию, без каких-либо действий по настройке.
2. Настроиться на другую станцию, вращая диск (JogWheel теперь — ручка тюнинга, а не перемотка). Переключение **дискретное**: каждый «тик» вращения — шаг на одну станцию вперёд/назад по списку (зафиксированному в разделе 4), без имитации непрерывной шкалы частот.
3. Включить/выключить приём одной круглой кнопкой (play/pause). Регулятора громкости в интерфейсе нет — громкость управляется системными средствами устройства/браузера.
4. Видеть живую визуализацию сигнала — спектр-эквалайзер (без переключения режимов, VU-метр и тумблер убраны). Статичного waveform больше нет — у живого потока нет фиксированной длины для его построения.
5. Установить приложение как PWA на экран телефона для быстрого повторного доступа.

## 4. Технические ограничения

- **Платформа:** веб, реализовано как PWA (manifest.json, service worker, иконки, кэш статики для офлайн-запуска оболочки — сам аудиопоток офлайн работать не может).
- **Хостинг/деплой:** Vercel (у автора уже есть аккаунт) — HTTPS и корректные заголовки для service worker из коробки, без ручной настройки `base` в конфиге, в отличие от GitHub Pages.
- **Архитектура:** без сервера — чистый клиентский SPA. Аудиопотоки идут напрямую из браузера к серверам радиостанций.
- **Источник аудио:** список кураторских интернет-радиостанций с прямыми stream-URL (зафиксирован, см. таблицу ниже).

**Явно исключены:**
- **SomaFM** — 4 сентября 2026 обновили Terms of Service, теперь прямо запрещают встраивание в сторонние приложения без письменного разрешения. Была первая идея по памяти — при проверке актуальных условий оказалось нельзя.
- **Deutschlandfunk Kultur** — рассматривали при добавлении 5-й/6-й станции: прямые stream URL публичны, но явного разрешения на встраивание в сторонние приложения не нашли, а немецкое законодательство об общественном вещании прямо говорит, что открытая доступность потока сама по себе не даёт права на встраивание третьими лицами. Тот же паттерн риска, что и у SomaFM — не стали добавлять.
- **C89.5 / Dance 89.5 (Сиэтл)** — рассматривали при добавлении 7-й/8-й станции как источник электронной музыки (жанр, которого не было в списке). Прямой stream URL раньше публиковался (`c895.org/mp3/`), но сейчас редиректит на главную страницу сайта независимо от типа клиента — реального адреса потока найти не удалось (спрятан за JS-плеером). Не добавлена не из-за юридического риска, а из-за отсутствия технической возможности честно проверить.
- **Radio Paradise** — официального документированного разрешения не нашли, только многолетняя неформальная терпимость сообщества. Не включена, можно добавить позже, если пользователь готов принять этот риск.

Остальные технические ограничения:

- **Нет фиксированной длительности:** у живого потока нет `duration`/`currentTime` в привычном смысле — JogWheel-скраббер переосмысливается в ручку переключения станций, а не позиции в треке. Механика **дискретная**: вращение продвигает индекс текущей станции по списку (как по пунктам меню), а не мапится на условную шкалу частот — уже есть звук detent-тика на каждый шаг, ложится на эту механику без доработки логики звука.
- **Визуализация:** только `AnalyserNode` через Web Audio API, один режим — спектр-эквалайзер. VU-метр и тумблер переключения режимов убраны полностью (зафиксировано: «убрать тумблер, оставить одну визуализацию») — упрощение, лишний элемент управления не нёс функциональной ценности. Статичный waveform (decodeAudioData всего трека) неприменим к живому потоку и убирается из UI.
- **Адаптивность:** обязательна — корректная работа и на десктопе, и на мобильных браузерах (responsive-вёрстка), т.к. это прямое требование PWA-сценария.
- **Сохранение состояния:** последняя станция сохраняется в `localStorage` и восстанавливается при следующем открытии (громкость сохранять нечего — регулятора нет). Автоплей при загрузке не запускаем (браузерные autoplay-политики всё равно не дадут стриму заиграть без клика) — восстанавливаем только выбранную станцию, играть начинает по нажатию play.
- **Обработка обрыва потока:** при ошибке/обрыве — автоматический retry **текущей** станции (несколько попыток с паузой между ними), без молчаливого переключения на другую станцию по списку (пользователь осознанно выбрал станцию — прыгать с неё неожиданно для него). Если ретраи исчерпаны — статус на дисплее («No signal»), переключиться на другую можно вручную диском.

## 5. UI-требования

- **Стиль:** функциональный минимализм в духе Дитера Рамса / Braun — «less but better», чистая геометрия, никакой лишней декоративности. Радиоприёмник даже органичнее ложится на этот стиль, чем плеер (Braun исторически известен именно радиоприёмниками — T3, RT 20).
- **Референс композиции:** конкретный компонент "Digital Rotary Radio Player" с [drams.framer.website](https://drams.framer.website) (открытая лицензия — свободное использование с указанием авторства; см. атрибуцию в README) — композиция скопирована один в один: круглая кнопка вкл/выкл слева, тонкие разделительные линии между секциями, крупная решётка встык, монохромный ряд засечек-станций, диск тюнинга по центру снизу.
- **Референс ручки тюнинга и кнопки play (обновлено):** визуальный стиль перенесён 1:1 из двух компонентов файла Figma Community ["Components inspired by Dieter Rams' design principles"](https://www.figma.com/design/Dgye0vkg7rg231FvWD9XLm/Components-inspired-by-Dieter-Rams--design-principles--Community-) (свободное использование, атрибуция в README):
  - **Ручка** — компонент "Dail 1": плоская нейтрально-серая заливка без градиента/блика (кольцо `#DCDCDC` → диск `#EEEEEE` с мягкой тенью → лицевая часть `#F7F7F7`), гнездо индикатора в цвет диска (`#EEEEEE`, ~20% диаметра ручки) с точкой-индикатором ~26% от гнезда. Ранее использовался стиль "Fingerin' Volume" с drams.framer.website (тёплый глянцевый градиент) — заменён этим более точным референсом.
  - **Кнопка play** — компонент "Button 4": квадратная плашка `#F7F7F7` (rounded 2px) с круглой кнопкой `#EEEEEE` внутри и той же точкой-индикатором по центру. Два состояния переданы через двойной bevel (inset-тени): выключено — выпуклая/приподнятая (мягкий внешний drop-shadow + выпуклый inset-бевел), включено — вдавленная внутрь (только вогнутый inset-бевел, без внешней тени) — по аналогии с реальной кнопкой питания, которая "утапливается" при включении.
- Обе плоские нейтрально-серые палитры (`#F7F7F7`/`#EEEEEE`/`#DCDCDC`) легли в основу общей цветовой темы — см. ниже.
- **Композиция:** один плоский корпус без карточек и вложенных панелей — секции разделены только тонкими линиями (`border`), не тенями/вставками.
- **Цветовая тема:** только светлая, полностью нейтрально-серая (обновлено — раньше была тёплая кремовая): фон/поверхности `#F7F7F7` → `#EEEEEE` → `#DCDCDC` (те же токены, что в ручке и кнопке play, вынесены в общие CSS-переменные `--color-cream*`), текст/декор тоже переведены на нейтральный серый (`--color-ink: #1c1c1c`, `--color-ink-soft: #8a8a8a`) — без желтоватого оттенка исходной кремовой темы. Единственный цветной акцент — оранжевая точка-индикатор (на кнопке play и на ручке тюнинга), цвет `#FF611A` (взят из Figma-референса, заменил прежний `#D9531F`) и унифицирован по всему проекту. Тёмная тема осознанно не делается (см. обоснование ниже, не изменилось).
- **Состав экрана:** круглая кнопка play/pause + дисплей в одном ряду (название станции + спектр-эквалайзер под ним, без переключателя режимов), решётка, ряд засечек-станций (кликабельны, активная ярче остальных, распределены равномерно по всей ширине), диск тюнинга по центру снизу (крутится — переключает станции дискретно). Регулятора громкости нет, загрузки файла нет.
- **Содержимое дисплея:** название станции показывается сразу же, без промежуточной надписи на статус `connecting` — **это осознанное решение, не баг и не недосмотр**. Причина: подключение к живому потоку занимает секунды, но об этом уже сигнализируют два независимых канала — кнопка play становится вдавленной сразу по клику (см. раздел 5, "Кнопка play"), и эквалайзер отдельно показывает плоскую линию-нуль, пока нет реального аудиосигнала (см. `Equalizer.tsx`). Отдельная текстовая надпись "Connecting…"/"CONNECTING…" поверх названия станции была признана избыточной и убрана — не возвращать её при последующих правках. Статус `error` — исключение: обрыв связи внешне неотличим от тишины (эквалайзер и так покажет плоскую линию, но это неоднозначно — то ли просто пауза, то ли реальная ошибка), поэтому только для него дисплей показывает «No signal» вместо названия. Регистр — обычный (Sentence case), капсом писать не нужно — уже дважды случайно возвращалось капсом при правках, это тоже не осознанный выбор. Шрифт названия станции — обычный системный (без кастомного `@font-face`). Пробовали Geist Pixel Circle (точки видны только при кегле ~140px+, на 22-24px неотличим от гладкого шрифта) и Micro 5 (LCD-стилистика, точки читаются на 24px) — по итогу решили вернуться к исходному системному шрифту.
- **PWA-требования:** иконка приложения, корректный prompt «Добавить на экран», рабочий офлайн-режим для UI-оболочки.

## 6. Метрики успеха (OKR)

**Цель:** рабочий и визуально сильный веб-радиоприёмник — одновременно кейс в портфолио и то, чем реально может пользоваться кто угодно по ссылке.

- **KR1:** MVP задеплоен по публичной ссылке, корректно открывается и работает в браузере на десктопе и на мобильном устройстве.
- **KR2:** Переключение между реальными станциями работает надёжно (обработка обрыва потока/CORS-ошибок без падения интерфейса).
- **KR3:** Live-эквалайзер работает без заметных лагов во время приёма.
- **KR4:** Установка как PWA работает без ошибок (manifest + service worker проходят Lighthouse PWA-аудит).
- **KR5:** Проект оформлен для портфолио — есть демо-ссылка, скриншоты/видео работы, краткое описание процесса разработки.
- **KR6:** Учебное задание курса по вайб-кодингу выполнено и сдано.
