# Radio — инструкции для агента

Веб-радиоприёмник (PWA) в эстетике Дитера Рамса / Braun. Полностью клиентское
SPA без бэкенда: аудиопотоки идут напрямую из браузера к серверам радиостанций.

Требования и все зафиксированные продуктовые решения — в [BRIEF.md](./BRIEF.md).
Прежде чем менять поведение или визуал, сверься с брифом: многие вещи там убраны
осознанно (регулятор громкости, VU-метр и тумблер режимов, загрузка файлов,
демо-треки, тёмная тема) — не возвращай их без явной просьбы.

Отложенные идеи и незакрытые хвосты — в [BACKLOG.md](./BACKLOG.md). Прежде чем
предлагать что-то «новое», загляни туда: возможно, это уже разобрано и отложено
с причиной. Бриф фиксирует принятые решения, бэклог — то, что ещё может быть
сделано.

## Стек

Vite + React 19 + TypeScript, Tailwind CSS v4, Zustand, Web Audio API,
Framer Motion, @use-gesture/react, vite-plugin-pwa, Vitest, oxlint.

## Команды

```bash
npm run dev       # dev-сервер
npm run build     # tsc -b && vite build (+ manifest и service worker)
npm run test      # Vitest
npm run lint      # oxlint
```

Перед сдачей изменений прогоняй `npm run lint` и `npm run test`; `npm run build`
дополнительно проверяет типы через `tsc -b`.

## Архитектура

```
src/
├── components/   # презентационные компоненты, без побочных эффектов
├── hooks/        # вся работа с Web Audio и <audio> изолирована здесь
├── store/        # Zustand: текущая станция и статус воспроизведения
├── lib/          # список станций и чистая логика без React:
│                 # spectrum.ts (биннинг FFT), grille.ts (шаг решётки)
├── types/        # общие типы (Station, PlaybackStatus)
└── styles/       # Tailwind + design tokens в @theme
```

Правило слоения: компоненты не читают стор и не трогают аудиограф потока —
станция и статус приходят пропсами из `App.tsx`, а всё вокруг `<audio>` и
`AnalyserNode` живёт в хуках. Это правило соблюдается без исключений: ни один
компонент не импортирует `usePlayerStore`.

Отклик на собственный жест — сознательно вне этого правила. Звук (`tiks`) и
вибрация вызываются прямо из компонента, которому принадлежит взаимодействие:
`PlayButton`, `JogWheel`, `StationTicks`. Это не побочный эффект над
состоянием приложения, а часть самого нажатия — протаскивать его через
`App.tsx` значило бы гонять колбэки ради индирекции. Обрати внимание: `tiks`
поднимает свой `AudioContext`, то есть Web Audio в компонентах всё-таки есть —
просто не тот граф, по которому идёт радиопоток.

Статические данные и чистые функции компоненты тоже импортируют напрямую:
`stations` в `StationTicks` и `JogWheel`, `lib/spectrum.ts` в `Equalizer`,
`lib/grille.ts` в `SpeakerGrille`, `lib/wheel.ts` в `JogWheel`.

### Ключевые места, где легко сломать

- **Звук интерфейса (`tiks`)** — громкость и мьют у библиотеки ГЛОБАЛЬНЫЕ.
  `useTiks` возвращает на компонент свой объект, но тот хранит только тему;
  звук играет модульный синглтон, и мастер-гейн у него один на всех. Поэтому
  настройки лежат одним объектом `UI_SOUND` в `lib/sound.ts` и подключаются
  из него везде. Не передавай `volume` в отдельный `useTiks`: он молча
  перебьёт общее значение, и уровень начнёт зависеть от порядка монтирования.
  Амплитуда каждого звука зашита в его генераторе и темой не регулируется —
  развести громкость диска и кнопки по отдельности библиотека не позволяет.

- **`useAudioAnalyser`** — граф кэшируется в `WeakMap` по элементу `<audio>`.
  `createMediaElementSource` можно вызвать для элемента только один раз за всю
  его жизнь, и этот кэш заодно защищает от двойного прогона эффекта в StrictMode.
  Не заменяй его на обычный ref.
- **Выход `<audio>` идёт через `AudioContext`.** Если контекст в состоянии
  `suspended`, воспроизведение стартует, событие `playing` приходит, а звука нет.
  Любой новый путь запуска должен вызывать `resume()`.
- **`useAudioPlayer`** — намерение играть держится в `wantsPlaybackRef`, а не в
  сторе: оно должно переживать ретраи и не вызывать ре-рендеров. Статус в сторе
  и этот ref обязаны сбрасываться согласованно.
- **`Equalizer`** — бины FFT группируются по логарифмической шкале, сглаживание
  асимметричное (быстрый подъём, медленный спад). Линейная выборка бинов делает
  правую половину столбиков неподвижной.

## Конвенции

- Комментарии — на русском, объясняют «почему», а не «что». Держи эту планку:
  неочевидные решения (аудиограф, биннинг FFT, шаг решётки) описаны причиной.
- Design tokens — только через CSS-переменные из `@theme` в `src/styles/index.css`.
  Не хардкодь цвета в компонентах; в инлайновых стилях используй `var(--color-*)`.
- Единственный цветной акцент во всём интерфейсе — `--color-accent` (`#FF611A`).
- Решётка динамика при ресайзе меняет **количество** точек, а не их размер.
- Решётка красится в два цвета: серые точки (`--color-ink-soft`) по всей панели
  и тёмные (`--color-ink`) только внутри круглого пятна по центру — зона
  прямого излучения динамика. Логика в `lib/grille.ts` (`centerDotCenters`):
  точка попадает в тёмную зону по своему ЦЕНТРУ, а не по пересечению с кругом —
  иначе точки на границе резались бы пополам и выглядели как грязь, а не как
  отверстия. `CENTER_RATIO` (0.4) — радиус пятна как доля меньшей стороны
  решётки, чтобы пятно оставалось кругом на любых пропорциях панели.

## Ограничения

- Бэкенда нет и не планируется. Никаких серверных зависимостей и ключей API.
- Список станций в `src/lib/stations.ts` зафиксирован. Каждый URL проверен на
  HTTPS, на `Access-Control-Allow-Origin: *` (без этого не работает эквалайзер)
  и на официальное разрешение использовать поток в стороннем плеере. Новую
  станцию добавлять только после такой же проверки — обоснования и список
  сознательно отклонённых станций в разделе 4 брифа.
- Деплой — Vercel, HTTPS.
